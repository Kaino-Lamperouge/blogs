低代码（Low Code）

低代码是用可视化配置 + 少量代码交付应用的开发方式，重点在"少写代码"，而不是"完全不写代码"。完全不写的那类叫零代码（No Code）。

核心组成

一套能用的低代码平台通常包含五部分：

  • 可视化编辑器：拖拽布局、属性面板、事件绑定；
  • Schema / DSL：把页面结构、逻辑、数据源描述成可存储的 JSON；
  • 渲染引擎：把 Schema 渲染成真实页面，各端各自实现；
  • 物料库：表单控件、图表、业务组件；
  • 数据源与逻辑编排：接口绑定、条件判断、变量流转。

一个最小 Schema

{
  "type": "form",
  "props": { "labelWidth": 96 },
  "children": [
    { "type": "input", "field": "name", "label": "姓名", "rules": [{ "required": true }] },
    { "type": "select", "field": "city", "label": "城市", "optionsFrom": "api://cities" }
  ]
}

渲染引擎读这份 JSON 生成表单，提交时按 field 收集数据。改需求往往只改 JSON，不用发版。

和零代码的区别

低代码零代码
使用者开发者为主，业务人员参与业务人员为主
定制能力可写自定义组件和逻辑受平台能力限制
复杂业务能承载容易卡住
典型形态表单引擎、页面搭建问卷、简单审批流

适合与不适合

适合：表单密集、流程固定、重复度高的中后台页面，例如审批、配置、报表。

不适合：强交互（编辑器、可视化大屏的复杂动画）、性能敏感场景、需求本身还在快速变化的产品。

落地难点

  1. Schema 设计：字段一旦上线就很难改，前期要留扩展位；
  2. 渲染一致性：H5、小程序、PC 各端渲染结果不同，需要统一的布局语言；
  3. 调试体验：出错时只有一份 JSON，报错信息必须能定位到具体节点；
  4. 版本与回滚：Schema 要能版本化，否则改坏一次就没法恢复。

低代码的收益来自"收敛重复劳动"，不是"让不会写代码的人写代码"。定位错了，平台会变成又一个难维护的遗留系统。
